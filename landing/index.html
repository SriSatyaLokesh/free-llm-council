Interactive Architecture

The 4-Stage Consensus Engine

Explore step-by-step how independent models deliberate, cross-examine, and synthesize truth.

Stage 1: Opening Positions

Parallel Investigation with Zero Peer Bias

Concurrency: 3-5 Models in Parallel

Each seated council model independently searches live web tools and analyzes the prompt. No model is allowed to see what peers are writing, ensuring diverse viewpoints and preventing groupthink.

// Model A (Llama 3.3 70B via Groq) Opening Stance: Recommends PostgreSQL + TimescaleDB for telemetry data due to mature tooling and relational JOIN capabilities. // Model B (DeepSeek-R1 via Ollama) Opening Stance: Recommends ClickHouse due to vectorized column-oriented storage, yielding 10x higher ingestion throughput and 70% lower disk footprint.
Stage 2: Multi-Round Debate

Direct Rebuttals & Persuasive Concessions

Rounds: 2 Rounds by Default

Models view each other's opening positions by name. Each model must challenge assumptions, cite counter-evidence, declare whether it is defending or updating its stance, and surface hidden drawbacks.

// Model A Rebuttal to DeepSeek-R1: "DeepSeek correctly highlights ClickHouse's raw ingestion speed. However, ClickHouse lacks ACID transactions on mutations and requires external coordination for complex JOINs. For teams with relational workloads, TimescaleDB avoids operational fragmentation." // Model B Concession: "Conceding Point: If immediate transactional updates are required, TimescaleDB is preferable. For pure append-only analytics at scale, ClickHouse remains mathematically superior."
Stage 3: Blind Peer Review

Anonymized Matrix Scoring Without Brand Bias

Scoring: 1 - 10 Factual Rubric

Candidate arguments are stripped of model names and randomized as Response A, Response B, and Response C. Models score peers objectively on factual correctness, clarity, and trade-off depth.

// Blind Review Aggregate Matrix: Response A (Llama 3.3): Factual: 9.2/10 | Reasoning: 8.8/10 | Rank: #2 Response B (DeepSeek-R1): Factual: 9.6/10 | Reasoning: 9.4/10 | Rank: #1 Response C (Qwen 2.5): Factual: 8.9/10 | Reasoning: 8.6/10 | Rank: #3 Consensus Agreement: High agreement on ClickHouse for analytics and TimescaleDB for hybrid CRUD.
Stage 4: Chairman Verdict & Caveman

Executive Verdict with Optional Token Compression

Compression: Up to 48% Token Savings

The designated Chairman LLM reviews the full transcript and review matrix, crafting an actionable executive summary with trade-offs, dissenting opinions, and confidence ratings.

// Chairman Verdict: DECISION: Adopt hybrid strategy — ClickHouse for time-series logs (>100k events/sec), PostgreSQL for metadata. Executive Report: Postgres vs. SQLite for MVP

An authentic deliberation conducted by Free LLM Council, synthesized into an actionable decision matrix.

Executive Verdict

Topic: "Postgres vs SQLite for MVP in 2026"

Consensus Confidence: 92% Chairman: Qwen 2.5 72B

1. Definitive Decision

Postgres. Managed & pooled from day one ($19–$25/mo via Neon or Supabase). Run real Postgres in Docker for local CI. Leverage Postgres primitives (pgvector, JSONB, SKIP LOCKED) to avoid spawning Redis or separate vector stores.

2. Strategic Tradeoffs

$25/mo cost floor vs $0/mo SQLite local file. In exchange, you eliminate data migration rewrites, gain multi-writer connection pooling, and prevent lock contention under concurrent load.

3. Consensus Dissent

The inversion clause: If the MVP is single-tenant, embedded, an offline desktop tool, or distributed at the edge, the council unanimously inverts to SQLite.

Frequently Asked Questions

Everything You Need to Know

Common questions about OpenCode, local setup, air-gapped operations, and model seating.

What is OpenCode and how does Free LLM Council use it?
OpenCode (opencode.ai) is the native local engine powering Free LLM Council. It runs a lightweight background HTTP service (defaulting to http://127.0.0.1:4096) that discovers your configured AI models, provides live web search and read-only workspace inspection tools, and enforces cryptographic canary protections so council members cannot alter your files.
Is Free LLM Council genuinely 100% free?
Yes. When connected to local OpenCode models (via Ollama or local backends), there are zero API token fees, credit card requirements, or rate limits. You can also connect free cloud tiers from Groq (Llama 3.3 70B on fast LPUs) and Google AI Studio (Gemini 2.0 Flash) without incurring monthly subscriptions.
How does Bring-Your-Own-Key (BYOK) work alongside free models?
Through our hybrid seating architecture, you can open the in-app Provider Key modal to input keys for Claude 3.5 Sonnet, GPT-4o, or OpenRouter. These frontier models are seated alongside your free local models in the roster. Keys are held purely in memory and are never persisted to disk or sent to our servers.
How does this differ from Andrej Karpathy's original prototype?
Karpathy's repository was an experimental single-file CLI script coupled to OpenRouter API keys. Free LLM Council expands this into a full sovereign studio: a modern single-window React interface, persistent sessions, project folders, mid-debate human steering, blind scoring rubrics, Caveman token reduction (~48% savings), and publication-grade PDF/ZIP report exports.
Can I run completely offline / air-gapped?
Yes. When you configure local Ollama models in OpenCode, no prompts, deliberations, or code ever leave your machine or local network. The entire deliberation, voting matrix, and report generation execute completely offline.
